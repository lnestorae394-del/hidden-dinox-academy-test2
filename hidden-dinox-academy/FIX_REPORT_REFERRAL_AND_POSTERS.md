# Отчёт: афиши и изображения, начисления при REFERRAL_MODE=off, выплаты, партнёрские ссылки

Работа велась над последней версией проекта (кабинет INVITE & EARN, баннеры, читалка). Production не изменялся: настройки Render и данные Firestore не трогались.

## 1. «Временная ошибка сервера — повторите» в «Афишах»

**Что найдено в коде.**
- `academy/admin-api.js`, функция `handler`: любая неожиданная ошибка превращалась в `503 «Временная ошибка сервера»`, а в лог Render писался только её код — без названия обработчика и текста.
- `academy/storage.js`, `firebaseStorage`: при запуске создаётся только объект бакета, существование и права НЕ проверялись. Ошибка Firebase Storage (бакет не создан, нет прав сервисного аккаунта) всплывала при загрузке/показе картинки и попадала в тот самый общий 503.

**Подтвердить конкретную причину на Render я не могу — нет доступа к логам.** Наиболее вероятно: Firebase Storage не включён для проекта или бакет называется иначе (для новых бакетов Firebase требует тариф Blaze).

**Исправлено.** Ошибка Storage теперь возвращается как `STORAGE_ERROR` с понятной причиной (`BUCKET_NOT_FOUND`, `NO_PERMISSION`, `NETWORK`) — в админке и в логе; запись в медиатеке при сбое не создаётся; «Админка → Диагностика» реально проверяет бакет (`bucket.exists()`); общий лог пишет название обработчика и сообщение (без секретов).

## 2. «При добавлении новой афиши пропадают прежние»

**Причина (подтверждена в коде).** Главная показывала две стандартные карточки (INVITE & EARN, книга) только пока в базе не было ни одного баннера (`learn-api.js`: `all.length ? live : DEFAULT_BANNERS`). Первая же созданная карточка их скрывала. В админке записи не удалялись — каждая афиша создаётся отдельным документом с новым ID.

**Исправлено.** Стандартные карточки — обычные записи CMS с постоянными ID `sys_invite`, `sys_book` (создаются один раз при открытии раздела «Афиши»); карусель = все опубликованные баннеры; порядок: INVITE & EARN, книга, затем по полю «Порядок». В админке — поиск, фильтры по статусу и типу, сортировка, счётчик, страницы; при ошибке список не очищается.

## 3. Почему при `REFERRAL_MODE=off` не начисляются деньги

Три причины, найденные в коде:
1. `academy/referral.js` (`modeOf`): переменная `REFERRAL_MODE` не задана → режим `off`.
2. `academy/referral.js` (`evaluate`): `const rewardMode = MODE === "off" ? null : MODE;` — в `off` запись о начислении не создаётся, приглашение остаётся в статусе «Подходит». Так задумано, но интерфейс теперь прямо пишет «Начисления временно отключены».
3. **Ошибка, мешавшая и в режиме `test`:** пересчёт вызывался только при открытии кабинета партнёром или по кнопке администратора. Ни postback депозита, ни привязка Trader ID его не запускали.

**Исправлено.** Пересчёт приглашённого запускается автоматически после каждого успешного postback и после привязки Trader ID (`autoReferral` в `academy/referral.js`, подключение в `academy/index.js`; логика postback не менялась). Начисление ровно одно (детерминированный ID записи журнала, транзакция).

**Режимы разделены:**

| Переменная | Значение по умолчанию | Действие |
|---|---|---|
| `REFERRAL_TRACKING_ENABLED` | включён | учёт приглашений и статусов |
| `REFERRAL_MODE` | `off` | начисления: `test` — тестовые, `live` — реальные |
| `REFERRAL_LIVE_CONFIRMED` | — | `1` обязателен для `live`; без него начисления выключены |
| `REFERRAL_PAYOUTS_ENABLED` | выключен | `1` — разрешить заявки на вывод |

**Реальные начисления НЕ включены.** В коде по умолчанию `off`; включение — только вами в Render (см. п. 6).

## 4. Выплаты (ручные)
Заявка от $50.00 → резерв в транзакции → `pending`. Админ: «В обработку» → вы переводите деньги через Pocket Partners → «Подтвердить выплату» (галочка + номер платежа) → `paid`, дата выплаты фиксируется. Кнопка не отправляет деньги. Отклонение — только с причиной, резерв возвращается один раз. Уведомление о сроках (24 часа, до 3 дней) — дословно на RU/EN/UA до и после отправки.

## 5. Партнёрские ссылки Pocket Partners
Раздел «Партнёрские ссылки»: партнёр, код, полная ссылка Pocket Partners (все параметры сохраняются), ссылка Academy `/academy/?via=код`, копирование, изменение, отключение, число закреплённых пользователей. Источник закрепляется на сервере один раз и только до привязки Trader ID. Разрешены только домены из `POCKET_LINK_HOSTS` (по умолчанию `u3.shortink.io`). Клик не считается регистрацией или FTD.

## 6. Ваши шаги в Render и Firebase
1. **Firebase Storage:** Firebase Console → Build → Storage → включить (может потребоваться тариф Blaze). Проверьте имя бакета; если не `ai-boost-10540.firebasestorage.app` — задайте `FIREBASE_STORAGE_BUCKET`. Сервисному аккаунту из `FIREBASE_KEY` нужна роль *Storage Object Admin*. После деплоя: «Админка → Диагностика» → «Firebase Storage: Работает».
2. **Тест начислений (рекомендуется на staging):** `REFERRAL_MODE=test`, `REFERRAL_PAYOUTS_ENABLED=1`. Пройдите цепочку реферала; начисление $10 (с пометкой test) появится сразу после postback FTD.
3. **Реальные начисления — только после проверки условий Pocket Partners** (разрешены ли такие вознаграждения и выплаты на торговый счёт) и юридической проверки: `REFERRAL_MODE=live` + `REFERRAL_LIVE_CONFIRMED=1` + `REFERRAL_PAYOUTS_ENABLED=1`. Проверьте в «Диагностике», что режим `live` без предупреждений.
4. **Firestore Rules:** добавьте правила из `firestore.rules.academy-proposal` (новая коллекция `partner_links`); проверьте на эмуляторе.
5. **Партнёрские ссылки:** если у ваших ссылок Pocket Partners другой домен, добавьте его в `POCKET_LINK_HOSTS`.
