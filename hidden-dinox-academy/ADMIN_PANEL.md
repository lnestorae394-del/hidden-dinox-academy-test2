Адрес: `https://hidden-dinox-academy-test2.onrender.com/admin/` · Ученики: `/academy/` → блок «Обучение» → `/academy/learn.html`

| Журнал действий | входы в админ-панель, публикации, роли, блокировки, изменения контента, медиа, афиши, импорт — кто, когда, что |
| Импорт курса | JSON курса → новый курс-черновик (ничего не публикуется) |

**Блоки урока:** заголовок, текст (жирный, курсив, списки, ссылки), термины, изображение, график / схема (редактируемый SVG из данных свечей и разметки), видео (YouTube, Vimeo, https), важное замечание (важно / предупреждение / редакционное дополнение / из книги / риск), пример ситуации, практическое и домашнее задание с критериями, тест с объяснениями, итог урока, PDF.

**Как публикуется обучение.** Ученики видят только *снимок* опубликованного курса. Правки черновика не видны до повторной публикации; публикуются только уроки «Готов к публикации»; черновики и правильные ответы тестов в браузер ученика не попадают. Тест проверяет сервер, ответы и объяснения ученик видит после попытки. Урок можно настроить «засчитывается только после теста».

## 2. Первый запуск (по шагам)

1. Обновите репозиторий файлами из архива (как в `DEPLOY_RENDER.md`, п. 8) и сделайте деплой.
2. **Firebase Storage** (нужен для загрузки файлов): Firebase Console → Build → Storage → Get started. Бакет по умолчанию — `ai-boost-10540.firebasestorage.app` (из Web Config проекта); если у вас другой — задайте `FIREBASE_STORAGE_BUCKET`. Для новых бакетов Firebase может потребовать тариф Blaze. Без Storage админ-панель работает, загрузка отвечает понятной ошибкой «Firebase Storage не настроен»; для изображений можно указывать https-ссылки.
3. **Первый Super Admin** — один из двух способов.

   **А. Через Render (без локального компьютера).** Войдите один раз в академию своим аккаунтом. Firebase Console → Authentication → Users → скопируйте **User UID** своей строки. Render → Environment → `ADMIN_BOOTSTRAP_UID` = этот UID → Save → деплой. В логах: «Одноразовое назначение Super Admin выполнено». После этого переменную можно удалить. Назначение выполняется один раз (маркер `system/admin_bootstrap_v2`). Используется UID, а не email: регистрация в академии не подтверждает владение почтой, и назначение «по адресу» мог бы получить тот, кто первым зарегистрирует этот адрес.

   **Б. Скриптом на своём компьютере:**
   ```bash
   npm install
   export FIREBASE_KEY='…JSON сервисного аккаунта…'      # Windows PowerShell: $env:FIREBASE_KEY='…'
   npm run set-role -- --email ВАШ_EMAIL --role super_admin            # просмотр
   npm run set-role -- --email ВАШ_EMAIL --role super_admin --apply    # запись
   ```
   Super Admin назначается только так — через админ-панель его выдать нельзя никому.
4. Откройте `/admin/`, войдите тем же email и паролем.
5. **Курс по книге:** «Импорт курса» → файл `content/hidden-reaction-course.json` → галочка → «Импортировать как черновик». Или из командной строки: `npm run import-course -- --file content/hidden-reaction-course.json --apply`.
6. Проверьте уроки, отметьте готовые «Готов к публикации», нажмите «Опубликовать» в курсе.

## 2а. Импорт курса и ошибка Firestore «invalid nested entity»

**Причина (исправлено).** Firestore не принимает массив внутри массива, а свечи учебных графиков хранились как `[[open, high, low, close], …]` — импорт курса по книге в настоящий Firestore падал с `3 INVALID_ARGUMENT: Property array contains an invalid nested entity`. Тестовая база раньше это ограничение не воспроизводила, поэтому тесты ошибку не видели.

**Что сделано.** В Firestore свеча хранится объектом `{ o, h, l, c }`; API админ-панели и ученика отдаёт её в исходной структуре `[o, h, l, c]`, как в JSON курса и редакторе, — без потерь и без изменения формата для остального кода. Тестовая база теперь отклоняет вложенные массивы и `undefined`, как настоящий Firestore. Повторный импорт курса с тем же `slug` не создаёт дубликат: ответ «Этот курс уже импортирован» и переход к существующему черновику.

**Импорт атомарен:** курс, модули и уроки записываются одной транзакцией — при ошибке не сохраняется ничего, поэтому прежний упавший импорт не мог оставить пустые модули. Если на Render виден курс с пустыми модулями, установите причину по фактическим данным (п. 2б), а не по догадке.

## 2б. Как проверить Render и данные Firestore

1. После деплоя откройте `/admin/` → **Диагностика** (только Super Admin, только чтение):
   - «Коммит GitHub» — версия, которую реально запустил Render (Render сам передаёт серверу `RENDER_GIT_COMMIT`, `RENDER_GIT_BRANCH` и `RENDER_SERVICE_NAME` — задавать их не нужно); сравните с последним коммитом в репозитории;
   - «Формат графиков исправлен (candles-objects-v1)» — если вместо этого красная метка, работает старый код;
   - по каждому курсу: статус, модули и **число уроков в каждом модуле**, уроки без модуля, опубликованный снимок.
2. То же из командной строки (с `FIREBASE_KEY`): `npm run inspect-courses`.
3. Если пустые модули принадлежат курсу, созданному до исправления, — это ручные модули без уроков или курс от старой версии кода; удалите такой черновик в админ-панели и импортируйте курс заново (повторный импорт с тем же `slug` откажет, пока старый курс не удалён).

## 6. Курс по книге — отчёт

**Изучено:** «The Hidden Reaction System», версия 1.0 (49 страниц, все разделы оглавления, а также раздел «Пример полного цикла сделки», стр. 39–40, которого нет в оглавлении) и `pattern.pdf` (2 страницы, 6 схем).

**Создано (черновик):** курс «HIDDEN DINOX — The Hidden Reaction System», 6 модулей, 29 уроков (23 тематических + итоговый тест в каждом модуле), 25 учебных графиков (22 отдельных блока «график» и 3 графика внутри примеров и практических заданий; SVG из данных, редактируются в конструкторе), 96 вопросов с правильными ответами и объяснениями со ссылкой на страницу, 23 практических задания с критериями.

1. Основа системы Hidden Reaction — стр. 3–8
2. Четыре этапа подробно: замедление, откат, накопление объёма, реакция, как соединяются — стр. 9–18
3. Вход: точка входа, ошибка большинства, структура рынка, подтверждение, где нельзя входить, ложные движения — стр. 19–32
4. Эмоции, дисциплина и риск, пример полного цикла, ошибки большинства — стр. 33–42
5. Чек-лист перед входом и финальный протокол — стр. 43–48
6. Паттерны Hidden: Reversal, Breakdown, Rejection, Trap, Compression, Liquidity — `pattern.pdf`

Правила автора приводятся с номерами страниц. Пояснения, которых нет в книге, вынесены в блоки «Редакционное дополнение» (10 штук). Все графики подписаны «учебная схема, синтетические данные, не котировка». В курсе есть дисклеймер о рисках; прибыль нигде не обещается.

**Требует вашего решения:**
1. **Название.** В задании — «Торговля от уровней M1 и долгосрочные экспедиции», но в книге нет ни «M1», ни «экспедиций», а «уровни» упомянуты один раз мимоходом (стр. 9). Курс назван по книге. Если M1 и экспедиции — часть вашей методики, нужен материал, где они описаны.
2. **Объём.** Книга не говорит, как определять объём на графике (индикатор, тики, поведение свечей). В уроках это отмечено как открытый вопрос.
3. **Конкретные параметры входа.** Нет таймфрейма, экспирации, места стопа и размера риска в числах — в курсе они не придуманы.
4. **Паттерны.** В `pattern.pdf` только схемы с подписями шагов, без текстовых правил. Связь паттернов с четырьмя этапами в уроках помечена как редакционное толкование.
5. **Обложка и иллюстрации** — по желанию загрузите свои в «Медиа» и замените в уроках.

**Где открыть:** `/admin/` → «Курсы и уроки» → «HIDDEN DINOX — The Hidden Reaction System» (после импорта, п. 2.5).

## 7. Telegram Mini App и AI Course Builder — что подготовлено

**Telegram (сервер готов, интерфейса ещё нет).** `POST /api/telegram/link { init_data }` привязывает Telegram к *вошедшему* аккаунту академии: подпись `initData` проверяется по официальному алгоритму Telegram (HMAC с ключом `WebAppData`), устаревшие (старше суток) и неподписанные данные отклоняются; один Telegram ID — один аккаунт (`telegram_links`); автоматического объединения по имени или username нет. Сохраняются ID, username, имя и фото из подписанных данных; админ-панель показывает их в карточке пользователя. Нужно от вас: бот в @BotFather → Mini App с адресом `/academy/` → токен в `TELEGRAM_BOT_TOKEN`. Следующий этап: кнопка «Привязать Telegram» в профиле, аватар, уровни и бейджи.

**AI Course Builder.** Формат импорта (`content/hidden-reaction-course.json`) и проверка контента (`academy/content.js`) — та точка, куда будущий конструктор будет сохранять черновики: всё импортируется только как черновик и проверяется человеком. Книга сейчас разобрана вручную; внешний AI API не подключён и книга никуда не отправлялась. Для подключения нужно ваше решение о провайдере и политике обработки данных.

**Уровни и бейджи** — пока не реализованы; данные для них уже собираются (завершённые уроки, результаты тестов в `lesson_progress`). Уровень не будет зависеть от депозита или объёма торговли.

## 8. Ограничения этой версии

- Участник команды (Team Member и выше) без собственного депозита открывает обучение напрямую: `/academy/learn.html` — главная страница академии по-прежнему ведёт его на шаги «брокер / депозит».

- Файлы медиа отдаются по длинной случайной ссылке (`/media/med_…`) без проверки входа — как обычный CDN; не загружайте в медиа личные данные.
- Списки пользователей и сводка читают коллекции целиком: подходит до нескольких тысяч пользователей; дальше нужна постраничная выдача.
- Текст урока — упрощённая разметка (жирный, курсив, списки, ссылки) с кнопками-подсказками, а не визуальный редактор Word-типа: так HTML из базы никогда не выполняется у учеников.
- График в конструкторе редактируется как данные (JSON свечей и разметки) с живым предпросмотром; визуального рисования мышью нет.
- Реальные Firebase Auth, Firestore и Storage здесь не проверялись (нет доступа); проверено на тестовой базе и тестовой замене входа.
