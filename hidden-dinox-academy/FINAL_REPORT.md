# HIDDEN DINOX ACADEMY — итоговый отчёт

## Этап «финальные исправления: $10 при активации доступа, причины отказа, шапка, вёрстка»

### Точки интеграции (найдены в коде)
- **Активация доступа** происходит на сервере в трёх местах: транзакция postback (`academy/postback.js` → `deposits.grantAccessIfReached`), привязка Trader ID (`academy/api.js`), решение администратора по депозиту (`admin-api.reviewDeposit`). Сразу после каждого из них вызывается пересчёт приглашённого (`referral.evaluateInvitee`) — в том же запросе, без открытия кабинета и без периодических задач.
- **Начисление** — `referral.evaluate`: одна запись журнала `reward_<режим>_<uid приглашённого>` (детерминированный ID) в транзакции вместе с балансом.

### Что изменено
- **$10 — при подтверждённой сервером активации доступа** приглашённого (по действующим правилам доступа; доступ по прежнему правилу «первый депозит от $40» теперь тоже квалифицирует). Клик, регистрация, произвольный Trader ID — не основание. Самореферал, тот же Trader ID/email, заблокированные и сотрудники — без начисления (статус «на проверке»).
- **Исторические активации — только с предпросмотром и подтверждением.** Сервер один раз фиксирует момент, с которого начисления активны (`system/referral_rewards_since_<режим>`). Доступ, открытый раньше (или в неизвестное время, в т.ч. восстановленный по старым данным), получает статус «ожидает проверки администратором» — без денег. «Админка → Партнёры и выплаты → Сверка исторических приглашений»: «Предпросмотр» (ничего не начисляет) → отметить строки → причина → подтверждение (супер-администратор). Повторное подтверждение не создаёт второе начисление.
- **Фоновая сверка прошлого этапа удалена**: она начисляла бы задним числом без подтверждения.
- **Найдена и исправлена ошибка в моём промежуточном коде**: в транзакции начисления запись создавалась до чтений — настоящий Firestore такую транзакцию отклоняет (тестовая база это поймала).
- **Причины отказа:** стандартные причины с готовыми переводами RU/EN/UA; своя причина — по-русски, переводится один раз при сохранении через DeepL (если задан `DEEPL_API_KEY`). Без перевода — русский оригинал сохраняется, на EN/UA пользователь видит нейтральную фразу на своём языке (сырой русский не показывается). Служебные заметки администратора к другим статусам пользователю не показываются.
- **Вывод:** шаг подтверждения суммы и Trader ID перед отправкой; кабинет обновляет баланс сам (раз в 20 с); честная пометка о ручных выплатах; уведомление об отклонённой заявке с причиной. Админка: полный Trader ID с кнопкой «Копировать», статусы «Ожидает обработки / В обработке / Выплачено / Отклонено».
- **Кнопка итогов:** «Посмотреть результаты» / “View results” / «Переглянути результати» — на главной и на странице курса; на финальном экране добавлена кнопка «К курсу».
- **Общая шапка и дизайн-система** (`public/academy/css/hd-system.css`): логотип + бренд + короткая подпись, компактный RU/EN/UA, ссылка навигации; на странице обучения подпись всегда «Обучение / Learning / Навчання», название курса — в содержимом. На ≤360 px ссылка сокращается до «←». В кабинете переключатель больше не растягивается. Правила переноса длинных строк — общие для всех курсов (курсы рисуются одними компонентами `learn.js` + `lesson-render.js`; новый курс получает всё автоматически — проверено курсом с очень длинными названиями).
- **Найдено вёрсткой:** в РУССКОЙ версии кабинета подписи плиток «Зарегистрировано», «Подтверждённый депозит» не помещались в плитку — плитки шире, переносы по слогам, шрифт не уменьшен.
- История основателя, баннеры, изображения, маскоты — не менялись.

### Безопасная сверка исторических приглашённых
1. После деплоя с `REFERRAL_MODE=live` сервер зафиксирует момент включения начислений. Новые активации доступа — $10 сразу.
2. «Админка → Партнёры и выплаты → Сверка исторических приглашений → Предпросмотр»: список приглашённых с доступом, открытым раньше (email, партнёр, дата прихода, основание и время доступа, «начисление уже есть»). Предпросмотр денег не начисляет.
3. Проверьте записи; отметьте те, кому положено $10; укажите причину; подтвердите (нужна роль супер-администратора).
4. Каждое начисление — отдельная запись журнала с постоянным ID: повторное подтверждение не начисляет дважды. Всё фиксируется в журнале аудита.

### Проверено / не проверено
- Всё ниже — **только локально** (тестовая база с правилами настоящего Firestore, тестовая замена входа). **На Render и в вашем Firebase не проверялось** — доступа нет.
- Отображение локализованной причины отказа проверено на уровне API (хранение оригинала, переводы, резервная фраза, смена языка — данные приходят все сразу); отдельного браузерного сценария отклонения с просмотром на EN/UA нет.
- Реальный перевод DeepL не вызывался (нет ключа); проверен подменённым сервисом.

## Этап «язык, прогресс, завершение курса, рефералы»

### Найденные причины
1. **Курс на главной не переводился при смене языка.** Название и описание курса переводит сервер; главная при смене языка перерисовывала данные, загруженные на прежнем языке, без нового запроса (`academy.js`, `render()`).
2. **На странице обучения не было переключателя языка**, а язык запросов вычислялся один раз при загрузке (`const qs = "?lang=" + LANG`) — всё менялось только после перезагрузки. Подпись «Пройдено N из M уроков» на странице курса была записана по-русски прямо в коде.
3. **Поля «Завершено модулей» и «Следующий шаг» никто не заполнял** — в `academy.html` это статичные «—».
4. **Урок с тестом считался пройденным только после отдельной кнопки** «Отметить урок пройденным». Пройти тест и перейти дальше — урок оставался незавершённым. Наиболее вероятная причина «прошёл весь курс, а прогресс неполный» (по вашей базе подтвердить не могу).
5. **Сервер не считал модули, следующий шаг и завершение курса** — отдавал только «N из M уроков».
6. **Кабинет партнёра и рефералы.** Надпись «денежная часть отключена» — потому что в Render не задан `REFERRAL_MODE` (режим `off`); код это показывает честно. Реальная проблема в коде: если приглашённые набрали $50, пока режим был `off`, после включения их $10 появлялись бы только когда партнёр откроет кабинет.

### Что исправлено
- **Язык без перезагрузки:** на главной, в уроке, на странице курса, на финальном экране, в кабинете партнёра и в истории основателя. Данные по каждому языку кэшируются (повторное переключение — без запросов); выбор сохраняется в браузере и в профиле (`users.lang`). В уроке выбранные ответы сохраняются, показанный результат теста перепроверяется на новом языке **без записи новой попытки**.
- **Прогресс — единый расчёт на сервере** (главная, страница курса, финальный экран) только из `lesson_progress`: уроки, процент, завершённые модули (все уроки модуля), следующий незавершённый урок, завершение курса (все уроки), дата завершения, средний лучший результат тестов. Существующие записи прогресса не меняются и учитываются как есть.
- **Успешный тест сам завершает урок** (в той же транзакции); повторные попытки — в той же записи, без дубликатов; открытие урока ничего не сбрасывает. Уроки без теста — по-прежнему кнопкой.
- **Финальный экран** (тексты RU/EN/UA — дословно ваши): открывается автоматически после последнего урока и повторно — с главной («Курс завершён — открыть поздравление») и со страницы курса. Показывает 29 / 29, модули, средний результат тестов (только из сохранённых данных), дату, статус. **Рейтинг** («лучше, чем N% участников») — только при 20 и более завершивших, по единому критерию (средний лучший результат тестов); иначе нейтральный текст. Кнопка «Вернуться в академию» / “Return to Academy” / «Повернутися до академії».
- **Рефералы:** фоновая сверка (через 30 с после запуска и каждые 15 мин при включённых начислениях) доводит начисления по уже сохранённым подтверждённым депозитам — без открытия кабинета, один раз на приглашённого.
- Изображения, маскоты, баннеры и дизайн карточек не менялись. На финальном экране использован уже существующий маскот.

- Реальные postback Pocket Partners, условия Pocket Partners о вознаграждениях, реальная выплата.

## Этап «депозиты, доступ $50, $10 партнёру, ручной вывод»

### Найденные причины (в коде)
1. **Доступ давал только ПЕРВЫЙ депозит, порог $40** (`academy/access.js`). Сумма всех депозитов считалась, но в коде было прямо записано «на доступ не влияет». Поэтому $20 + $30 не открывали академию.
2. **Одинаковые пополнения склеивались.** Без `POSTBACK_EVENT_ID_PARAM` ключ события — отпечаток (тип, Trader ID, click_id, сумма, валюта): второе настоящее пополнение на ту же сумму молча считалось повтором.
3. **Страница депозита переставала проверять** после недостаточного депозита и писала, что «повторные пополнения не засчитываются».
4. **Клиентская обёртка** `getDepositStatus` отбрасывала новые поля ответа (найдено браузерным тестом).

### Что исправлено
- **Доступ — по сумме подтверждённых депозитов в USD от $50.00**: каждый депозит — отдельная запись (`deposit_events/{id}`: ID события, Trader ID, сумма, валюта, статус, время, источник — postback); засчитывается один раз в транзакции; не учитываются повторы, неподтверждённые, отклонённые, с неподтверждённой валютой, на чужой Trader ID.
- **Достигнутый доступ сохраняется** (`referrals/{traderId}.academy.access_granted`: время, сумма, событие) и больше не закрывается.
- **Переход без отключений:** момент перехода записывается один раз (`system/access_rule_v50`); у кого первый депозит от $40 подтверждён ДО него — доступ сохраняется. Новые — только по сумме от $50.
- **Повторы:** с ID события — строго по ID; без него — повтор в течение 15 минут = дубль, то же событие позже → «ожидает проверки» (не теряется и не засчитывается само); администратор засчитывает или отклоняет — с причиной, подтверждением, один раз, с записью в журнале.
- **$10 партнёру** — ровно один раз, когда у приглашённого подтверждённая сумма достигла $50 (одна запись журнала на приглашённого, транзакция); дополнительные депозиты того же человека новых начислений не дают; доступ по прежнему правилу $40 не квалифицирует.
- **Вывод:** от $50 доступного баланса; получатель — подтверждённый Trader ID партнёра (ввод полного ID, сверка; подставить Trader ID приглашённого нельзя); резерв атомарно и один раз; `paid` — только ручным подтверждением администратора после перевода (номер платежа, время, администратор); ни таймер, ни время статус не меняют; отклонение — с причиной, резерв освобождается один раз.
- **Интерфейс:** «Подтверждено: $20 из $50. Осталось внести $30», «Вы можете пополнить тот же аккаунт — подтверждённые депозиты суммируются», «ожидает подтверждения» (RU/EN/UA); страница продолжает проверку раз в 30 секунд — мгновенного обновления не обещаем.
- **Админка:** поиск по UID, email, Trader ID; фильтр «депозиты на проверке»; в карточке пользователя — все депозиты, сумма и прогресс до $50, основание доступа, реферер и статус квалификации; кабинет партнёра — начисления, баланс, заявки, Trader ID получателя, история выплат.

### Переменные Render
| Переменная | Значение | Когда |

| `FIREBASE_KEY`, `POCKET_POSTBACK_SECRET` | как раньше | всегда |

### Проверка на staging (по шагам)
1. Отдельный сервис Render и отдельный проект Firebase (тестовые события не должны попасть в рабочую базу). Задать `REFERRAL_MODE=test`, `REFERRAL_PAYOUTS_ENABLED=1`.
2. Партнёр открывает кабинет, копирует ссылку; второй пользователь регистрируется по ней, привязывает Trader ID.
3. Тестовый postback FTD $20 → у пользователя «$20 из $50, осталось $30», у партнёра статус «FTD подтверждён», $0.
4. Тестовый postback redeposit $30 → академия открывается сама (в течение ~30 с), у партнёра +$10 (test). Повторите тот же postback — сумма и начисление не меняются.
5. Ещё redeposit $100 — у партнёра по-прежнему $10.
6. Пополните баланс партнёра до $50 (ещё 4 реферала или ручная корректировка с причиной) → заявка на вывод с полным Trader ID партнёра → в админке «В обработку» → «Подтвердить выплату» с номером тестового платежа; вторая заявка → «Отклонить» с причиной — резерв вернулся.

- **Причина «курс остаётся на русском»:** курс в вашей базе был импортирован до появления переводов; переводы лежат в файле курса, но в Firestore не попали без действия «Обновить переводы» и повторной публикации. - Цепочка начисления (сервер): ссылка `?ref=` → привязка к новому аккаунту один раз → подтверждённый Trader ID → доступ к академии → FTD, подтверждённый postback Pocket Partners с секретом → антифрод → **ровно одно начисление $10** (детерминированный ID записи журнала, транзакция). - **Не проверено (нет доступа):** условия Pocket Partners о допустимости реферальных вознаграждений и выплат на торговый счёт; реальная доставка postback от Pocket Partners. Реальные начисления не включены.
