### 3. Язык: найденная причина и исправление
- **Причина «курс остаётся на русском»:** курс в вашей базе был импортирован до появления переводов; переводы лежат в файле курса, но в Firestore не попали без действия «Обновить переводы» и повторной публикации. Подтвердить по вашей базе я не мог (нет доступа), но код этот сценарий полностью объясняет.
- **Исправление:** переводы курса поставляются с приложением; сервер подставляет их к опубликованным урокам, у которых переводов в базе нет. Каждая строка подставляется только при совпадении отпечатка русского оригинала, поэтому устаревший перевод не показывается — он **обнаруживается**: «Админка → Диагностика → Перевод опубликованных курсов» показывает, сколько уроков переведено полностью и сколько строк устарело по каждому языку.
- Выбор языка сохраняется в браузере и в профиле пользователя (`users.lang`) — переживает обновление страницы, повторный вход и вход с другого устройства; ID уроков, ответы и прогресс не зависят от языка.
- Книга в читалке: RU — оригинал, EN и UA — переводы (см. раздел 0).

### 4. Реферальная программа
- **Почему `REFERRAL_MODE=off`:** переменная не задана в Render, а по умолчанию система в режиме `off` (учёт приглашений работает, начисления и вывод выключены). Это настройка, а не ошибка кода; изменить переменные Render могу не я — значения ниже.
- Цепочка начисления (сервер): ссылка `?ref=` → привязка к новому аккаунту один раз → подтверждённый Trader ID → доступ к академии → FTD, подтверждённый postback Pocket Partners с секретом → антифрод → **ровно одно начисление $10** (детерминированный ID записи журнала, транзакция). Клик, регистрация, неподтверждённый или повторный депозит не начисляют.
- Вывод: от $50, пользователь **вводит полный Trader ID**, сервер сверяет его с подтверждённым Trader ID аккаунта (иначе отказ без резерва); резерв атомарный; заявка в админке с UID, Trader ID, суммой, датой и временем, ID и статусом; «Подтвердить выплату» — только вручную после перевода через Pocket Partners; отклонение — с причиной, резерв освобождается один раз; корректировки — с причиной и аудитом.
- **Не проверено (нет доступа):** условия Pocket Partners о допустимости реферальных вознаграждений и выплат на торговый счёт; реальная доставка postback от Pocket Partners. Реальные начисления не включены.

### 5. Переменные Render
| Переменная | Значение | Когда |
|---|---|---|
| `FIREBASE_KEY` | JSON сервисного аккаунта | всегда |
| `POCKET_POSTBACK_SECRET` | ≥ 24 символов, тот же, что в URL postback | всегда |
| `POSTBACK_DEFAULT_CURRENCY` | `USD` | если Pocket Partners подтвердили, что {SUMDEP} в USD |
| `FIREBASE_STORAGE_BUCKET` | имя бакета | если не `ai-boost-10540.firebasestorage.app` |
| `REFERRAL_MODE` | `test` | **staging**: проверка начислений (помечаются test) |
| `REFERRAL_PAYOUTS_ENABLED` | `1` | staging и рабочий режим — разрешить заявки |
| `REFERRAL_MODE` | `live` | **только после вашего подтверждения** |
| `REFERRAL_LIVE_CONFIRMED` | `1` | обязательно вместе с `live`, иначе начисления выключены |
| `POCKET_LINK_HOSTS` | домены ссылок Pocket Partners | если не `u3.shortink.io` |

5. **Реальные начисления** — только после проверки условий Pocket Partners: `REFERRAL_MODE=live` + `REFERRAL_LIVE_CONFIRMED=1` + `REFERRAL_PAYOUTS_ENABLED=1`.
6. **Firestore Rules:** применить `firestore.rules.academy-proposal` (после проверки на эмуляторе).
7. Если у ссылок Pocket Partners другой домен — добавить в `POCKET_LINK_HOSTS`.
