# Telegram-бот Hidden Dinox

Код: `bot/core.js` (вся логика, без зависимости от Telegraf), `bot/index.js` (подключение Telegraf), видео `bot/assets/hidden_dinox_dostup_otkryt_v3.mp4` (вне `public/`, сайтом не раздаётся). В `server.js` — одна строка подключения после академии; ошибка модуля бота не роняет сайт.

## Переменные окружения (Render → Environment)
| Переменная | Значение |
|---|---|
| `BOT_ENABLED` | `1` — включить бота (без неё бот не запускается) |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather (та же переменная уже используется для входа из Mini App). Допускается `BOT_TOKEN`. В коде токена нет |
| `ADMIN_TELEGRAM_ID` | ваш числовой Telegram ID (можно несколько через запятую). Узнать: напишите @userinfobot |
| `BOT_WEBHOOK_URL` | `https://hiddendinox.com/telegram/webhook` (рекомендуется на Render) |
| `BOT_WEBHOOK_SECRET` | случайная строка ≥ 24 символов (A–Z, a–z, 0–9, `_`, `-`); Telegram передаёт её в заголовке, чужие запросы отклоняются |
| `BOT_START_VIDEO_FILE_ID` | необязательно: file_id видео для /start (иначе берётся из Firestore `bot_config/start_video`) |
| `BOT_WEBAPP_URL`, `BOT_SUPPORT_URL` | необязательно; по умолчанию `https://hiddendinox.com` и `https://t.me/hiddendinoxsupport` |

Без `BOT_WEBHOOK_URL` бот работает в режиме polling (для локальной разработки). Один токен нельзя одновременно использовать в двух местах (две копии polling или polling и webhook) — Telegram ответит ошибкой 409.

## /start
Пользователь сохраняется в `bot_users/{telegram_id}`. Бот отправляет видео через `sendVideo` и две кнопки: «🟢 Открыть Hidden Dinox Academy» (Mini App `https://hiddendinox.com`) и «Поддержка» (`https://t.me/hiddendinoxsupport`).
file_id: при первой отправке бот загружает файл из `bot/assets` и сохраняет полученный file_id в `bot_config/start_video`; дальше видео отправляется по file_id без загрузки. Получить file_id заранее: напишите боту `/videoid` с аккаунта администратора — бот пришлёт видео и file_id (его можно записать в `BOT_START_VIDEO_FILE_ID`). Если Telegram отвергнет сохранённый file_id (например, после смены бота), видео будет загружено заново автоматически.

## Публикации (только ADMIN_TELEGRAM_ID; посторонним бот на эти команды не отвечает)
- `/newpost` — пошагово: текст (форматирование Telegram сохраняется) → фото или видео либо `/skip` → кнопки → предпросмотр → «Сохранить черновик» или «К отправке». Кнопки — каждая с новой строки `Название | https://ссылка`; несколько в одном ряду — через `||`; до 10 кнопок, ссылки `https://` или `tg://`. Подпись к фото/видео — до 1024 символов, текст — до 4096. `/cancel` — отмена.
- `/posts` — последние публикации, статусы и итоги рассылок.
- `/editpost ID` — изменить черновик (`/skip` — оставить, `/nomedia`, `/nobuttons` — убрать). Разосланные публикации не изменяются.
- `/deletepost ID` — убрать публикацию из списка (с подтверждением). Сообщения у пользователей не удаляются, история сохраняется.
- `/broadcast ID` — предпросмотр, число получателей и кнопка подтверждения. Только после неё начинается рассылка.
Мастер хранит состояние в Firestore — перезапуск сервера его не обрывает.

## Рассылка
- Получают все, кто запускал бота и не заблокировал его (`bot_users.status = active`). Бот не может первым написать человеку, который его не запускал.
- Аудитория фиксируется в момент подтверждения; пакеты по 25 пользователей, ≈ 25 сообщений в секунду.
- 429 — пауза на `retry_after` и повтор; 5xx и сетевые ошибки — до 3 попыток; 403 «бот заблокирован» — пользователь помечается недоступным; прочие ошибки — «ошибка», пользователь остаётся в базе.
- Прогресс — одно обновляемое сообщение администратору: отправлено, ошибок, заблокировали бота.
- Повторной отправки нет: отметка доставки создаётся до отправки; после перезапуска сервера рассылка продолжается с места остановки; сообщение, отправка которого была прервана перезапуском, не повторяется (считается «без подтверждения»); повторный запуск той же публикации запрещён; аренда задания исключает две копии сервера на одной рассылке.
- Рассылка идёт внутри процесса сервера: если Render усыпит или перезапустит сервис, она продолжится после запуска.

## Firestore (только сервер, Admin SDK)
`bot_users`, `bot_config/start_video`, `bot_admin_state`, `bot_posts`, `bot_post_history`, `bot_broadcasts`, `bot_broadcast_targets`, `bot_deliveries`. Правила Firestore не менялись.

## Проверка на тестовом боте (до основного)
1. Создайте тестового бота в @BotFather, задайте его токен и ваш ID на тестовом сервисе Render; `BOT_ENABLED=1`, `BOT_WEBHOOK_URL`, `BOT_WEBHOOK_SECRET`.
2. `/start` с двух аккаунтов: видео, обе кнопки (Mini App открывается внутри Telegram), второй раз видео приходит мгновенно (по file_id).
3. С постороннего аккаунта `/newpost` — бот молчит.
4. `/newpost` с фото и двумя рядами кнопок → предпросмотр → `/broadcast ID` → подтверждение: оба аккаунта получили пост, прогресс обновлялся.
5. Заблокируйте бота с одного аккаунта, разошлите новый пост: «заблокировали бота: 1».
6. Повторное подтверждение той же публикации — отказ «уже разослана».
