# Ручная проверка на тестовом Render (ветка audit-2026-10)

Сайт: `https://hidden-dinox-academy-test2.onrender.com` · Firebase: `ai-boost-10540` · Production и `main` не трогаем.

## 0. Перед деплоем (локально, с настоящим Express 5)
```
git fetch && git checkout audit-2026-10
npm ci            # или npm install
npm ls express    # ожидается express@5.x
npm test
```
В выводе `npm test` должна быть строка `# Express: настоящий (5.x.x)` (а не «тестовая реализация»), итог — без `not ok`.

## 1. Деплой ветки на тестовый сервис
Render → тестовый сервис → **Settings → Build & Deploy → Branch** = `audit-2026-10` → **Manual Deploy → Deploy latest commit**.
В логе сборки — установка зависимостей без ошибок; в логе запуска — `Server running`.

## 2. Переменные (Render → Environment) — сначала БЕЗ TRUST_PROXY
| Переменная | Значение |
|---|---|
| `MAIL_PROVIDER` | `resend` |
| `RESEND_API_KEY` | ключ из Resend (только здесь) |
| `MAIL_FROM` | `Hidden Dinox Academy <onboarding@resend.dev>` |
| `APP_BASE_URL` | `https://hidden-dinox-academy-test2.onrender.com` |
Лог запуска: `ℹ️ восстановление пароля: письма Hidden Dinox Academy через resend`.

## 3. TRUST_PROXY по реальной цепочке
Админка → **Диагностика** → `request_ip`: найдите свой настоящий IP в `xff_chain`.
Последний → `TRUST_PROXY=1`. Справа ещё K адресов → `1 + K` (только если цепочка это показывает). Нет вашего IP → не задавать.
После перезапуска: `ip_seen_by_server` = ваш IP, `ip_limit_active: true`. Блок `mail`: `configured: true`, `provider: resend`.

## 4. Письмо сброса пароля
1. `/academy/index.html` → «Забыли пароль?» → **email владельца аккаунта Resend** (пока домен не подтверждён, Resend доставляет только ему).
2. Сообщение на сайте — общее («если аккаунт существует…»). Повторите с несуществующим email — сообщение то же.
3. Письмо: тёмный фон, логотип, «Сбросить пароль», срок ≈1 час, резервная ссылка. Проверьте «Спам». Отправитель — `MAIL_FROM`.
4. Кнопка → `…/academy/reset-password.html` (адрес без кода после загрузки) → новый пароль ×2 → «Пароль изменён» → вход с новым паролем.
5. Та же ссылка повторно → «Ссылка недействительна».
6. Четвёртый запрос на тот же email в течение часа → «Слишком много попыток».
7. Лог Render: `forgot-password <хеш>: письмо отправлено (resend)` — без email, ссылок и ключей. Для несуществующего email — `аккаунт не найден… (письмо не отправлено)`.

## 5. Запасной путь (по желанию)
Временно удалите `MAIL_PROVIDER` → «Забыли пароль?» → придёт стандартное письмо Firebase (ссылка Firebase). Верните переменную.
