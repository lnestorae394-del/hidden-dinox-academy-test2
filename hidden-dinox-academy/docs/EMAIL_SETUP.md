# Письма восстановления пароля — Resend (бесплатный тариф) или SMTP

Как это работает: «Забыли пароль?» → `POST /api/auth/forgot-password` (наш сервер на Render) → Firebase Admin SDK
`generatePasswordResetLink(email)` создаёт настоящий одноразовый код → сервер отправляет фирменное письмо (Resend API или SMTP)
→ кнопка «Сбросить пароль» открывает `/academy/reset-password.html` → новый пароль проверяет и сохраняет Firebase Auth
(`confirmPasswordReset`). Сервер пароль **не устанавливает** и без кода из письма сменить пароль нельзя.

Пока почта не настроена, сайт автоматически использует прежнее стандартное письмо Firebase — восстановление не ломается.

## 1. Переменные Render (Environment)

| Переменная | Значение | Обязательно |
|---|---|---|
| `MAIL_PROVIDER` | `resend` | да |
| `RESEND_API_KEY` | ключ из Resend (начинается с `re_`) — **только на Render**, не в коде и не в Git | да |
| `MAIL_FROM` | адрес, разрешённый в Resend (см. п. 2), например `Hidden Dinox Academy <onboarding@resend.dev>` для проверки, позже `Hidden Dinox Academy <no-reply@ВАШ-ДОМЕН>` | да |
| `APP_BASE_URL` | `https://hidden-dinox-academy-test2.onrender.com` (без `/` в конце) | да — из него строится ссылка в письме |
| `MAIL_REPLY_TO` | адрес поддержки для ответов | нет |
| `TRUST_PROXY` | `1` — см. п. 1.1 | рекомендуется: включает лимит по IP |

### 1.1. IP клиента за прокси Render (`TRUST_PROXY`)

Сервер определяет IP только по правилам Express (`req.ip`) и **не верит** заголовкам `X-Forwarded-For`, `CF-Connecting-IP`, `True-Client-IP` напрямую — клиент может прислать их сам.

- **`TRUST_PROXY` не задан** (сейчас): запросы на Render приходят через прокси, и без доверия к нему настоящий IP неизвестен. Лимит «10 запросов с IP за 15 минут» тогда **не применяется** (иначе он действовал бы на всех посетителей сразу). Лимиты по email (3 письма в час на адрес) и общий (200 писем в час) работают всегда. В логе один раз: `⚠️ forgot-password: … TRUST_PROXY не задан`.
- **`TRUST_PROXY=1`**: Express доверяет одному прокси (балансировщику Render) и берёт адрес, который добавил он; значения, дописанные клиентом слева, игнорируются. Эта же переменная уже используется для `POSTBACK_ALLOWED_IPS`.

**Как выбрать значение на Render — по реальной цепочке прокси, а не наугад:**
1. Задеплойте **без** `TRUST_PROXY` (лимиты по email и общий работают и так).
2. Откройте админку → **Диагностика** → блок `request_ip`. Поле `xff_chain` — заголовок `X-Forwarded-For` вашего собственного запроса, как его получил сервер.
3. Узнайте свой настоящий IP (любой сервис «мой IP») и найдите его в `xff_chain`.
   - Ваш IP — **последний** в цепочке → `TRUST_PROXY=1`.
   - Справа от него ещё K адресов → `TRUST_PROXY = 1 + K`. Ставьте больше 1 **только** если цепочка это действительно показывает.
   - Вашего IP в цепочке нет → не задавайте `TRUST_PROXY` и сообщите разработчику содержимое блока.
4. Задайте значение, дождитесь перезапуска, снова откройте Диагностику: `ip_seen_by_server` = ваш IP, `ip_limit_active: true`.
5. Слишком большое значение опасно: тогда сервер возьмёт адрес, который клиент приписал сам, и лимит по IP можно обойти. `TRUST_PROXY=true` сервер не применяет.

## 2. Resend — что сделать

1. Регистрация: https://resend.com → **API Keys → Create API Key** (права *Sending access*). Скопируйте ключ один раз — Resend показывает его только при создании — и вставьте в Render как `RESEND_API_KEY`.
2. **Пока нет своего домена** можно отправлять только с `onboarding@resend.dev`, и Resend доставит письмо **только на email владельца аккаунта Resend**. Этого достаточно, чтобы проверить весь путь на себе, но ученикам письма приходить не будут.
3. **Для писем ученикам нужен подтверждённый домен** (после покупки `hiddendinox.academy` / `.com`):
   Resend → **Domains → Add Domain** → домен → добавьте у регистратора DNS-записи, которые покажет Resend (SPF/DKIM — TXT, для обратного адреса — MX) → дождитесь статуса **Verified**.
   Затем на Render: `MAIL_FROM = Hidden Dinox Academy <no-reply@ваш-домен>`.
4. Ограничения бесплатного тарифа (дневной/месячный лимит писем) смотрите на странице тарифов Resend. Код дополнительно ограничивает отправку: 3 письма на адрес в час, 10 запросов с IP за 15 минут, 200 писем в час на весь сервис.

## 3. Бесплатная альтернатива до покупки домена — SMTP

Код поддерживает SMTP без дополнительных библиотек (только с шифрованием TLS).
Например, отдельный Gmail-ящик академии: включить двухэтапную аутентификацию → **Пароли приложений** → создать пароль.

| Переменная | Значение |
|---|---|
| `MAIL_PROVIDER` | `smtp` |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` (TLS) или `587` (STARTTLS) |
| `SMTP_USER` | адрес ящика |
| `SMTP_PASS` | пароль приложения (не основной пароль) |
| `MAIL_FROM` | `Hidden Dinox Academy <тот же адрес>` |

Письма придут ученикам с подписью «Hidden Dinox Academy». Суточные лимиты ящика уточните у почтового сервиса.

## 4. Firebase

- Ничего менять не нужно: ссылка создаётся Admin SDK через ключ сервиса `FIREBASE_KEY`, который уже задан на Render.
- Страница `/academy/reset-password.html` использует веб-ключ Firebase из `config.js`. Если в Google Cloud Console у этого API-ключа включены ограничения по сайтам (HTTP referrers) — добавьте туда домен сайта (сейчас `hidden-dinox-academy-test2.onrender.com/*`, позже — новый домен).
- **Authentication → Settings → Authorized domains**: держите там домен сайта (нужно для запасного пути через стандартное письмо Firebase).

## 5. Проверка реальным письмом

1. Задайте переменные (п. 1), дождитесь перезапуска, в логах — строка `… через resend`.
2. На сайте: «Забыли пароль?» → **email владельца аккаунта Resend** (пока домен не подтверждён) → сообщение «Если такой аккаунт существует…».
3. Письмо: тёмное, с логотипом и кнопкой «Сбросить пароль», отправитель — значение `MAIL_FROM`. Проверьте папку «Спам».
4. Кнопка → `…/academy/reset-password.html` → новый пароль дважды → «Пароль изменён» → вход с новым паролем.
5. Повторно откройте ту же ссылку → «Ссылка недействительна». Логи Render: строки `forgot-password <хеш>: письмо отправлено (resend)` без email и ссылок.
6. Если письма нет: логи Render → `forgot-password … ошибка отправки resend: RESEND_403 — …` (обычно `MAIL_FROM` не разрешён: домен не подтверждён или получатель не владелец аккаунта).
