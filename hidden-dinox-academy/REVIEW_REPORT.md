# HIDDEN DINOX ACADEMY — проверка архива

Дата проверки: 2026-10-22

## Проверено локально

- `npm test`: успешно, включая 112 тестов API/логики, wiring, CLI-скрипты и поиск секретов.
- `python3 tests/mutation-check.py`: 67 из 67 искусственных поломок обнаружены тестами.
- `node --check`: `server.js`, `academy/admin-api.js`, `academy/learn-api.js`, `academy/telegram.js`, `public/admin/admin.js`, `public/academy/js/lesson-render.js` — синтаксис корректен.
- `content/hidden-reaction-course.json`: прошёл валидацию существующими функциями CMS; 6 модулей, 29 уроков, 96 вопросов, 23 практических задания, 22 блока типа chart.
- `tests/run-all.sh`: браузерный E2E не удалось запустить в этой среде: Chromium не может открыть `127.0.0.1` и возвращает `ERR_BLOCKED_BY_ADMINISTRATOR`. Это ограничение среды проверки, а не доказательство ошибки приложения.
- Настоящие Firebase Auth, Firestore, Firebase Storage и Render не проверялись: доступов к ним в среде нет.

## Исправлено во время проверки

Обнаружено, что просмотр урока проверял дату отложенной публикации, но POST-маршруты отправки теста и завершения урока проверяли только наличие документа опубликованного урока. При знании ID можно было отправить тест/завершение до даты показа.

Исправлено в `academy/learn-api.js`: тест и завершение теперь проверяют, что курс опубликован, уже видим ученику (или пользователь — сотрудник), а урок входит в опубликованный снимок курса. Добавлены регрессионные проверки; `npm test` после исправления проходит.

## Осталось перед production

1. **Медиа публичны по случайной ссылке.** `GET /media/:id` не требует входа и ставит публичный Cache-Control. Не загружать конфиденциальные материалы; если они нужны, добавить проверку доступа и приватное кеширование.
2. **Правила Firestore — предложение, не production-конфигурация.** `firebase.json` указывает на `firestore.rules.academy-proposal`; файл сам предупреждает, что старые правила проекта нужно предварительно объединить. Не выполнять `firebase deploy --only firestore:rules` с этим файлом без сверки текущих правил.
3. **Telegram UI не завершён.** Серверный маршрут привязки есть, но кнопка привязки в профиле, показ аватара и уровни/бейджи в кабинете ученика не реализованы. Требуется `TELEGRAM_BOT_TOKEN` и настройка Mini App.
4. **Storage/Render не проверены в настоящем окружении.** Нужны проверка бакета, прав сервисного аккаунта, переменных окружения и деплоя на staging.
5. **E2E браузера не подтверждён этой средой.** Повторить `sh tests/run-all.sh` в обычном окружении с установленным Playwright Chromium.
6. **Публичный API масштабируется ограниченно.** Админ-панель читает до 500 пользователей за запрос и некоторые dashboard-коллекции целиком; для роста нужны пагинация и агрегаты.
7. **Курс:** в JSON 22 блока `chart`, в отчёте/документации ранее указано 25 графиков. Перед импортом стоит сверить подсчёт визуальных графиков с содержимым уроков.

## Рекомендованный порядок запуска

1. Сделать резервную копию репозитория и проверить изменения в отдельной ветке/staging.
2. Развернуть код без изменения production Firestore rules.
3. Назначить `super_admin` только локальным скриптом с правильным `FIREBASE_KEY` после входа своего аккаунта.
4. Проверить `/admin/`, импортировать курс как черновик, проверить несколько уроков и медиа.
5. Провести проверку в реальном браузере и на телефоне.
6. Публиковать курс только после ручной проверки содержания и графиков.
